## Confirmed（已确认）

- **引擎/技术**：Godot 4.7，2D，mobile 渲染器；语言 GDScript；数据驱动（Resource / JSON），由 DataLoader 加载。
- **类型**：回合制卡组构筑 Roguelike，UI 简化版。
- **职业**：仅保留「战士」一个职业，无多职业切换、无职业选择界面。
- **核心循环**：战斗 → 奖励（选卡 / 金币 / 遗物）→ 地图节点选择 → 下一节点 → Boss → 单局结束。
- **战斗**：能量限制出牌；敌人意图（Intent）可见；格挡（Block，下回合开始时清空，可扛过敌人攻击）；状态系统（Buff / Debuff）。
- **难度**：已**归位至正式值 `normal`**（详见 `BALANCE_TABLE.json`：敌人伤害 ×1.0、HP ×1.0、单场最多 3 敌、精英频率 0.18+，按幕递增）。原 v1「×0.65/×0.8 低难度」折扣已于 2026-08-17 撤销；`WORLD_SETTING.md §5.4` 的「火种低难度」叙事需随归位值复核（见知识库未完成项）。
- **美术**：**明亮扁平卡通风、暖色系**，与 StS 暗黑哥特手绘形成明显差异（详见 `ART_STYLE.md`）。
- **内容规模（当前）**：**3 幕串联**（Act1 陶原初探 10 层 / Act2 炽窑升焰 9 层 / Act3 窑主终焰 8 层，每幕 1 个 Boss）；**48 张卡**（含 5 张召唤卡）、**20 个敌人**（11 原生 + 9 新增，含 2 个 Boss）、**11 个遗物**（含窑主印记）、**10 个状态**（炽热/塑形/釉裂/受潮/灰蚀/回火/蓄焰/釉光/焦渴/指挥）。
- **随从/召唤系统**：设计稿 v1 已 ratify 并实现闭环（SUMMON_SYSTEM_DESIGN.md），第 5 个 Build「召主 Summoner」；含召唤栏 UI（§6.1 登场高亮→暗态被玩家立绘遮挡→行动时提亮置顶→回合后恢复遮挡）；SummonVerify 全 8 项通过，2026-08-25 闭环完成。
- **目标平台**：**手机端优先（竖屏 Portrait）**，PC 仅作为开发与测试预览；UI 必须为触摸操作设计、竖屏布局。详见下方《UI 规范（手机端，强制）》。
- **多幕扩展（Act 2/3）**：已完成 3 幕串联（2026-08-18，见 `MULTIACT_EXPANSION_DESIGN.md`），含幕间比例回血、存档 v2、幕缩放（1.0/1.15/1.30）、敌池隔离；击败**最后一幕** Boss 才整局胜利。
- **世界观 / 叙事**：已落地 v2「陶土世界·炽窑」设定（`WORLD_SETTING.md`），与明亮暖色卡通风一致，Boss 为悲剧型前辈而非传统恶役。

## UI 规范（手机端，强制）

> 自本版本起，所有 UI（战斗 HUD / 地图 / 奖励 / 商店 / 休息 / 事件 / 弹窗）必须遵循以下手机端标准，作为 UI 验收的硬性约束。违反此规范的 UI 视为未完成。

- **基准分辨率**：竖屏 `720 × 1280`（9:16），由 `project.godot` 的 `window/size/viewport_*` 设定；其它比例手机通过 stretch（`canvas_items` + `aspect=keep`）等比缩放适配。
- **方向**：竖屏（Portrait）。布局以单列 / 窄宽堆叠为主，**禁止依赖横屏或宽屏**做关键信息排布。
- **最小字号**：正文与数值 ≥ **20px**；重要信息（HP、能量、敌人意图、状态）≥ **26px**；面板标题 ≥ **32px**；弹窗大标题 ≥ **56px**。当前占位 UI 仍偏小，后续美术细化时必须落到舒适区间（建议正文 24–28、重要 30+、大标题 64+）。
- **最小可点热区**：任何可交互控件 ≥ **64×64px**，优先 **80×80px**；手牌卡面宽度 ≥ **120px**。
- **对比度**：文字与背景必须满足可读对比（暖色界面用深褐 `#40332E` 一类），**禁止低对比灰字**。
- **自适应原则**：所有 UI 用锚点 / 容器（Anchors、Container）自适应，**不写死像素坐标**；地图等自绘内容基于 720×1280 基准计算坐标。
- **验收**：任何新增 / 修改 UI 必须在该基准下可正常触摸操作；PC 端以竖屏预览（letterbox 黑边）验证，不能只看横屏。
